Security model

Checks and balances for a school-safe system.

Access starts with verified teachers, stays tied to a school and class, and keeps student evidence behind teacher-controlled review.

Plain-English promise

Teachers control setup, students use lightweight classroom accounts, data is stored on Australian servers, class comparisons are de-identified, and free-text submissions are approved through the teacher dashboard.

Verified teacher entry

Teacher signup is limited to approved school email domains with password-based login and email confirmation.

Teacher-created students

Students do not self-register or use email. Teachers can issue a first-name-and-initial username or a codename for a specific class.

School and class ownership

Every class and student belongs to one school, creating clear boundaries for dashboards and permissions.

School data boundaries

The system checks each signed-in teacher's school before showing class records, so teachers only see the students and classes connected to their school.

Human review gate

Learning evidence, feedback reports, and shareable responses are routed through teacher review before wider use.

Private student evidence

Students can see their own profile and progress, but not another student's private records.

De-identified class comparison

Inside the class, students may see non-identified peer responses or totals for comparison, not named student records.

Australian data hosting

Student and class data is stored on Australian servers.

Safe demo mode

Teacher previews seed local demo data, keeping trial runs separate from real student accounts.

Balance point: automation can surface patterns, but the teacher remains the accountable reviewer for class membership, student evidence, and any intervention decisions.
